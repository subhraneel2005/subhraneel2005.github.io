# reproducing x fan-out problem in code

a small experiment inspired by **chapter 1's fan-out example portion** of **designing data-intensive applications (ddia)** by martin kleppmann.

i also made a video walking through the whole thing: <Link href="https://x.com/subhraneeltwt/status/2075034293546705035" target="_blank">x.com/subhraneeltwt/status/2075034293546705035</Link>

## goal

simulate and compare two fan-out strategies - **push** (write path) and **pull** (read path) - for delivering tweets to a user's timeline in a twitter-like social feed system.

the main idea is that there is a fundamental tradeoff between write amplification and read amplification, and real-world systems often use a hybrid approach.

## concepts covered

- **push** - writing data to all followers at tweet time
- **pull** - collecting data from followed users at read time
- **merge** - combining pushed and pulled data for a unified feed
- **scalability** - handling millions of followers and reads
- **load balancing** - distributing fan-out work across the system

## strategies

### push (write fan-out)

when an author tweets, the post is immediately written to every follower's timeline.

<Image src="/x-fanout/a1.png" alt="push fan-out diagram" />

- **work** = number of followers.
- **cost**: 500,000 writes for a vip tweet; 10 for a regular tweet.
- **tradeoff**: expensive for authors with many followers (write amplification), but readers see new content instantly with zero read-time computation.

```typescript
import type { Post } from "../models/Post.js";
import type { User } from "../models/User.js";

export class PushStrategy {
    work = 0;

    pushTweetToAllFollowers(author: User, post: Post){
        for (const f of author.followers){
            f.timeline.push(post)
            author.posts.push(post)
            this.work++
        }
    }
}
```

### pull (read fan-out)

posts live only on the author's timeline. when a user opens their feed, they iterate over everyone they follow and collect their posts.

<Image src="/x-fanout/a2.png" alt="pull fan-out diagram" />

- **work** = number of followed users × their posts.
- **cost**: depends on how many people you follow and how many posts they've made.
- **tradeoff**: cheap on writes (no fan-out needed), but expensive on reads (read amplification).

### vip-only pull variation

a hybrid variant pulls only posts from vip authors. this hints at twitter's real-world approach: vip (celebrity) tweets are pushed to all followers, while regular users' tweets are pulled at read time.

<Image src="/x-fanout/a3.png" alt="vip-only pull diagram" />

```typescript
import type { User } from "../models/User.js";

export class PullStrategy {
    work = 0;

    pullNewTweetsToTimeline(user: User){
        user.timeline = [];

        for (const f of user.following){
            for (const p of f.posts){
                user.timeline.push(p)
                this.work++
            }
        }
    }

    pullOnlyVipTweetsToTimeline(user: User){
        user.timeline = [];

        for (const f of user.following){
            if(f.isVip){
                for(const p of f.posts){
                    user.timeline.push(p)
                    this.work++
                }
            }
        }
    }
}
```

### entry point

```typescript
import { Post } from "./models/Post.js";
import { User } from "./models/User.js";
import { PullStrategy } from "./strategies/Pull.js";
import { PushStrategy } from "./strategies/Push.js";
import { regular, vip } from "./utils/generateUsers.js";

const regularTweet = new Post(
    "regPost-8112303C-480B-4F61-A321-A580A12EB771",
    regular,
    Date.now()
)

const vipTweet = new Post(
    "vipPost-F3D42E78-5FB6-4AD7-B131-C5595B767E1C",
    vip,
    Date.now()
)

const normalUser = new User(
    "normalUser-A98F7702-A932-4935-9E09-A4346A903F2B",
    false
)

function simulatePush(){
    console.log("SIMULATING PUSH");

    const push = new PushStrategy();

    push.pushTweetToAllFollowers(regular, regularTweet)
    console.log("WORKS COUNT FOR REGULAR TWEET PUSH: ", push.work)

    push.work = 0

    push.pushTweetToAllFollowers(vip, vipTweet)
    console.log("WORKS COUNT FOR VIP TWEET PUSH: ", push.work)

}

function simulatePull(){
    console.log("SIMULATING PULL");

    regular.posts.push(regularTweet)
    vip.posts.push(vipTweet)

    normalUser.following.push(regular)
    normalUser.following.push(vip)

    const pull = new PullStrategy()

    pull.pullNewTweetsToTimeline(normalUser)

    console.log("WORKS COUNT FOR PULL:", pull.work);
    console.log("TIMELINE SIZE:", normalUser.timeline.length);
}

function vipOnlyPull(){
    console.log("SIMULATING VIP ONLY PULL");

    const pull = new PullStrategy()

    normalUser.timeline = []

    pull.pullOnlyVipTweetsToTimeline(normalUser)

    console.log("WORKS COUNT FOR PULL:", pull.work);
    console.log("TIMELINE SIZE:", normalUser.timeline.length);
}

function runAll(){
    simulatePush()
    simulatePull()
    vipOnlyPull()
}

runAll()
```

## what i learned

### write amplification vs. read amplification

the push strategy shifts cost to the write path. for a celebrity with 500k followers, one tweet causes 500k write operations. the pull strategy shifts cost to the read path - reading a feed means checking every followed user's posts.

### the hybrid sweet spot

real systems (twitter, instagram) use both:
- **vip users** → push their tweets to a fan-out cache at write time.
- **regular users** → pull tweets from followed users at read time.
- a user's feed is then merged from both sources.

### strategy pattern

the project cleanly separates the two algorithms into interchangeable strategy classes (`PushStrategy`, `PullStrategy`), making it easy to compare and swap them.
